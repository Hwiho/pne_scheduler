### R1 — 알림을 켜는 것부터 끄고 복구하는 것까지

- R1a: 기존 연결 표시 옆에 시작/안전 종료, 마지막 heartbeat, 실행기 버전,
  최근 오류·지연 건수를 표시한다. 사용자/데이터 저장소 단위 제어로 다른 실행기를
  종료하지 않는다. PID만 보고 강제 종료하거나 웹 API에서 임의 프로세스를 제어하지 않는다.
- 메인 반복과 10초 balloon 대기 중에도 종료 요청을 확인한다. 정상 종료는 잠금 해제와
  종료 상태 기록까지 확인; 오래된 실행기가 응답하지 않으면 ‘종료 미확인’으로 남긴다.
  잠금 파일을 지우는 것으로 종료를 대신하지 않는다.
- **OS 전송 요청 / 화면 표시 확인 / 사용자 확인을 구분**한다. 현 `notified_at`은
  실제로 읽었다는 증거가 아니다. 전송 뒤 기록 전 장애에서 정확히 한 번 전달은
  보장하지 않고, 재시도 가능성·시각·중복 식별자를 남긴다. 일괄 지연 알림은 요약하고
  개별 미확인 기록은 보존한다. 100건 동시 만료에도 heartbeat가 굶지 않게 한다.
- 기본은 사용자가 직접 시작. 로그인 시작은 허용 여부를 확인하고 켜기/끄기를 대칭 제공하는
  선택 기능이다. 현재 balloon을 현대식 toast로 교체할지는 Windows 스파이크 후 결정한다.
  사용자의 현재 세션에서 테스트 알림이나 창을 임의로 띄우지 않는다.
- R1b: 일정 변경 전 새 알림/취소될 알림·이미 확인한 항목을 비교하고 1회 적용한다.
  과거 발송 이력은 수정하지 않고 일정 버전을 추가; 완료/보관 상태는 암묵적으로 해제하지 않는다.
- 종료 기준: 독립 Windows 시험 세션에서 시작→중복 시작 차단→종료→재시작,
  전송 실패·강제 종료 후 복귀·24시간 지연·시계 변경·집중 지원/알림 차단을 시험한다.
  UI의 ‘연결됨’만으로 실제 알림 전달 통과 처리하지 않는다.

### R2 — 백업은 파일 생성이 아니라 복원이 되는 것으로 완료

- 공통 로컬 서비스에서 SQLite backup API로 DB 복사본을 만들고 무결성을 검사한다.
  라이브러리·복구 문서와 사용자가 선택한 프로젝트를 별도 manifest/해시로 묶는다.
  외부 경로의 프로젝트는 **포함/미포함**을 먼저 보여 주며 임의 폴더 전체를 수집하지 않는다.
- DB 스냅샷만으로 여러 파일의 동일 시점이 보장되지 않는다. 공유 저장소 유지보수 잠금,
  실행기 종료 확인, 쓰기 유예 후 캡처를 설계한다. 구버전/다른 클라이언트의 쓰기 중단을
  확인하지 못하거나 캡처 중 변경이 감지되면 완성본으로 게시하지 않는다. manifest에
  스키마·앱 버전·캡처 시각·제외 목록 기록. 미저장 웹 초안은 명시적 저장/내보내기가
  필요하며 서버 폴더 백업에 포함됐다고 표시하지 않는다.
- MVP 복원은 **새 빈 데이터 폴더**로만 하고 원본은 보존한다. 경로 이탈/절대 경로/링크/
  과도한 압축 해제 크기·손상/미지원 스키마를 거부; 실제 앱으로 프로젝트·방법·보관 이력을
  다시 연다. 복원 직후 알림 실행기는 자동 시작하지 않고 지연 알림 목록을 검토시킨다.
- 장애/용량 부족/사용자 취소 시 기존 데이터 불변. 부분 백업은 성공 목록에 넣지 않는다.
  민감한 원자료·키·로그는 기본 제외하며 외부 전송은 없다. 백업 파일 암호화는 별도 정책 결정.
- 종료 기준: 활성 WAL/동시 쓰기·파일 변경·잘못된 ZIP·디스크 부족·구 스키마 시험,
  새 경로 복원 후 행 수/파일 해시/알림 확인 이력 대조. 백업 성공만으로 통과하지 않는다.

### R3 — 사라지지 않는 배포 이력과 안전한 업데이트

- 현재 Windows ZIP은 실제 압축 해제본 검사를 통과했다. Artifact
  `12135807455`는 조회 시 **2026-11-17 11:56 UTC 만료 예정**이며 장기 배포본이 아니다.
  승인된 커밋의 검증된 ZIP·SHA-256·빌드 출처·라이선스/의존성 목록·알려진 한계를
  버전별 묶음으로 보관하는 Release 절차를 준비한다. 이번 문서 개정에서 Release를 게시하지 않는다.
- 같은 파일 해시를 기준으로 검사→배포를 연결하고, 재빌드했다면 다시 검사한다.
  서명 전후 바이트가 다르면 서명된 최종 파일을 검증한다. 서명 인증서·기관 반입 결정은 사용자 몫.
- 프로그램과 데이터 버전을 각각 표시하고 새 프로그램 폴더로 수동 업데이트한다.
  데이터 스키마 변경 전 R2 백업/복원 확인; 구버전이 신 DB를 만나면 읽기/쓰기를
  보수적으로 차단한다. 프로그램 폴더 교체만으로 DB downgrade가 된다고 안내하지 않는다.
- 개인 연구자료 없는 진단 묶음을 선택적으로 생성하고 포함 파일을 미리 보여 준다.
  자동 업로드·자동 업데이트·관리자 서비스 설치는 범위 밖이다.
- 종료 기준: Python 없는 오프라인 Windows에서 새 설치/재실행/업데이트/이전 백업 복원,
  한글 경로, 사용자 데이터 불변, 서명 상태/백신 정책 표시. DPI·실제 알림은 N4b 기록으로 분리.

### R4 — 배치 파일 생성기를 실험 작업대로

- 기존 셀 입력·C-rate 행렬·미리보기를 재사용한다. 셀/로트(선택)/기준용량/실제 전류/
  출력 등급을 표로 검토하고 선택한 행만 새 부분 배치로 생성할 때 제외 목록을 명시한다.
  같은 시험의 `배치 ID → 셀 ID → 레시피 버전/해시 → 산출물 해시`를 재조회할 수 있게 한다.
- 공통 서비스가 `planned/running/staged/succeeded/failed/cancelled/interrupted` 상태,
  성공 파일 수·남은 셀·오류를 관리한다. 웹 HTTP와 Tk는 같은 상태를 표시한다.
  파일 생성 진행과 실제 장비 시험 진행은 다른 상태이며 장비 실행 중이라고 표시하지 않는다.
- 기존 전체 배치 원자성을 보존한다. **셀별 진행은 임시 결과**, 최종 폴더 승격 전에는
  성공 파일로 다운로드시키지 않는다. 취소는 안전한 작업 경계에서만, 승격 중에는 기다린다.
- 파일 게시와 작업 DB 갱신은 단일 트랜잭션이 아니다. 승격 직후 중단 시 시작 과정에서
  배치 ID/manifest/해시로 상태를 대조한다. 재시도는 새 attempt/새 폴더, 자동 덮어쓰기 금지.
  기존 manifest 가져오기는 읽기 전용이며 재검토/장비 승인을 자동 승계하지 않는다.
- 종료 기준: 3셀 기준용량 80/90/100mAh의 1C=80/90/100mA 재파싱 대조,
  100셀×3조건 부하에서 출력 누락 0, 중간 실패·취소·승격 직후 종료·이중 클릭,
  앱 재시작 후 재조회/해시 변조 탐지. UI 응답성 측정은 R5 공통 규칙 사용.

### R5 — 더 작은 박스, 더 명확한 조건, 측정한 뒤 최적화

- 기본/전문가 보기에서 같은 모델을 사용한다. 세로 카드에는 대표 C-rate·mA·SOC/DOD·
  휴지·반복 횟수만 요약하고 상세는 선택 패널에 둔다. 저장 프리셋의 원본 버전과
  현재 변경 여부를 표시하며 기본 입력은 숫자, 단위는 한 곳에만 둔다.
- 그룹 대표 변수는 명시적 매핑/단위/대상 목록이 있는 값만 연결한다. 같은 이름의 필드라고
  숨은 자식 전체에 적용하지 않는다. ‘같은 실험에 적용’은 변경 전/후 및 대상 수 확인과 1회 undo.
  대표 변수 모델을 새로 넣기 전 기존 공통 일괄 편집을 재사용할 수 있는지 확인한다.
- 고정/계산 추정/미상 시간과 안전 상한을 다른 표시로 유지한다. ‘전류 대 시간’ 그림을
  추가한다면 설계도임을 명시하고 CCCV taper·전압 종료 시간을 실측처럼 그리지 않는다.
- 먼저 20/100/500모듈과 100셀×3조건에서 선택·입력 반영·펼치기·미리보기/메모리 기준선을
  같은 Windows PC에 기록한다. **잠정 목표**: 가벼운 선택/편집 반응 p95 200ms 이내,
  긴 작업은 1초 안에 진행 상태 표시. 아직 측정된 성능이 아니며 기준 PC 확인 후 확정한다.
  필요한 경우만 지연 상세 로딩/목록 가상화를 적용하고 기존 확장 횟수·응답 크기 테스트 유지.
- 종료 기준: 웹 320/390/1440px, Tk 1024×768 및 100/150/200% DPI, 키보드만으로
  추가→편집→이동→접기→undo→저장. 필수 버튼·단위·오류 잘림 없음, 편집 중 값 유실 없음,
  웹/Tk 동일 프로젝트의 출력·게이트 일치. 실제 화면 인수는 별도 시험 세션에서 한다.

### R6 — 실측 결과를 안전하게 전류 계산에 연결

- 처음부터 모든 장비 포맷을 지원하지 않는다. 비식별 활성화/derating 대표 파일 각각과
  정답 셀/로트·방전 구간·용량을 받은 **한 형식**부터 preview-only 수입으로 시작한다.
  기존 QPEED SOC-setting 수입은 유지하고 공통 provenance 규칙만 맞춘다.
- [Gate H의 용량 계보 계약](GATE_H_PLAN.md)을 적용한다. 원본 해시·열/단위·cycle/step·
  채택 이유를 남기고 모호한 매칭은 차단한다. 명시적으로 적용하기 전 출력 전류는 바뀌지 않는다.
- Formation/derating/cycle 단계별 기준 선택은 사용자 정책 확인 후 별도 스키마 변경으로
  진행한다. 직접 입력 값을 설계용량이라고 소급 해석하지 않는다. 실행 중 얻을 미래 용량을
  미리 만들어 둔 SCH가 자동 참조한다고 약속하지 않는다.
- 종료 기준: 단위·부호·결측·중복·재측정 사례, 사용자 정답과 허용오차 합의,
  미리보기=재파싱 전류, 출처 추적/undo, 기존 수동 프로젝트 출력 불변. 샘플 부재는 이 항목만 막는다.

### R7 — 추가 프리셋은 완성된 기본 단계의 조합으로

- 첫 후보는 **율별 용량+회복 사이클**: 기존 rate matrix는 여러 독립 파일,
  새 프리셋은 한 절차 안의 여러 rate와 회복 단계라는 차이를 명시한다.
- 둘째는 **고온저장 잔존/회복 용량**: 저장 전/후 레시피와 보관 기록을 묶되
  챔버 온도 제어·측정 전압 자동 수집은 포함하지 않는다. SOC 준비 단계는 기존 미검증 게이트 유지.
- OCV–SOC와 GITT는 추가 후보만 유지한다. SOC 필드·OCV 장비 지원과 실험 정책이 먼저이며
  GITT 시간표 생성은 확산계수 분석이 아니다. 상세 근거·기존 후보는 [주 로드맵 §1](ROADMAP.md) 참조.
- 각 프리셋에 목적, 필요한 입력, 단계 구성, 확정/추정 시간, 미검증 필드, 검토용 예상 스텝을
  함께 제공한다. ‘표준’ 이름으로 자동 인증하지 않으며 새로운 전류/전압/펄스 기본값을 추정하지 않는다.
- 종료 기준: 수작업으로 조합한 같은 원시 스텝과 결과 동등, 그룹 편집/저장/undo,
  단일 DC-IR 선택 유지, 각 산출물의 F/PV 등급 보존. 한 후보씩 실제 필요를 확인한 뒤 추가한다.

재검토 시에는 각 R 항목에 구현 커밋·테스트·실사용 인수를 각각 기록한다. 최초 조사에서는
문서·코드 근거만 검토했으며, 후속 U1–U3 구현·테스트는 위 절에 별도 기록했다.
Windows 알림 실사용 검사로 세지 않는다. **이번 사용성 개선 다음 권고는 R1a + R2**다.

## 1차 구현 규칙

### 방법 버전

- 저장 파일은 append-only이다. 생성 완료된 임시 파일을 배타적으로 게시하여 동시에 저장해도 같은 버전 파일을 덮어쓰지 않는다. 손상된 버전의 파일명도 재사용하지 않는다.
- 버전 비교는 같은 현재 셀 조건에서 확장한 스텝을 비교한다. 기록 간격·DC-IR IR 설정·용량 초기화도 비교하며, 이름/설명/저장 장비 변경은 별도 표시한다. 상세는 최대 20줄로 제한한다.
- 동일 조건을 먼저 대응시키고 바뀐 구간을 스텝 종류로 비교한다. 동일 종류 스텝을 추가했다고 기존 스텝이 변경된 것처럼 표시하지 않는다.
- 미리보기는 디스크·현재 실험을 바꾸지 않는다. 토큰은 프로젝트 전체, 특정 저장 버전의 내용, 추가/교체 방식에 결합한다. 변경된 미리보기로 적용하면 거부한다.
- 기존 ‘최신 버전 불러오기’ API는 호환성을 유지한다. 새 화면은 명시적 버전과 검토 토큰으로 적용한다. 저장되었다는 이유로 내보내기 제한을 완화하지 않는다.

### 고온저장 보관함

- 영구 삭제는 제공하지 않는다. `archivedAt`과 이동/복원 이력을 추가하는 비파괴 DB 마이그레이션을 사용한다.
- 보관함은 화면 정리/알림 중지 기능이며 실제 실험 종료를 뜻하지 않는다. 진행 중인 기록의 경과시간은 계속 계산된다.
- 보관 시 기존 `notify_enabled`도 꺼 두어 보관함 열을 모르는 구버전 실행기의 새 알림을 막는다. 원래 설정은 별도 보존하고 복원 시 되살린다.
- 복원해도 원래 확인·전송·다시 알림 상태를 지우지 않는다. 진행 중이고 알림이 켜져 있으면 기한이 지난 미확인 알림이 발송될 수 있음을 적용 전에 설명한다.
- 새 실행기는 알림을 claim한 뒤 전송 직전에 상태를 다시 확인한다. 이미 OS에 전송 중인 알림까지 취소할 수 있다고 보장하지 않는다.
- 기존 API의 기본 목록은 보관함을 제외한다. 새 화면은 보관함 포함 조회를 사용해 검색·복원과 브라우저 기록 중복 검사를 처리한다.
- API와 실행기가 동시에 시작해도 스키마 확인·열 추가를 한 트랜잭션으로 직렬화한다. WAL 전환의 즉시 잠금 오류는 최대 10초 범위에서만 재시도하며, 이력 조회에는 시료 ID 인덱스를 사용한다.
