## 1차 구현 규칙

### 방법 버전

- 저장 파일은 append-only이다. 생성 완료된 임시 파일을 배타적으로 게시하여 동시에 저장해도 같은 버전 파일을 덮어쓰지 않는다. 손상된 버전의 파일명도 재사용하지 않는다.
- 버전 비교는 같은 현재 셀 조건에서 확장한 스텝을 비교한다. 기록 간격·DC-IR IR 설정·용량 초기화도 비교하며, 이름/설명/저장 장비 변경은 별도 표시한다. 상세는 최대 20줄로 제한한다.
- 동일 조건을 먼저 대응시키고 바뀐 구간을 스텝 종류로 비교한다. 동일 종류 스텝을 추가했다고 기존 스텝이 변경된 것처럼 표시하지 않는다.
- 미리보기는 디스크·현재 실험을 바꾸지 않는다. 토큰은 프로젝트 전체, 특정 저장 버전의 내용, 추가/교체 방식에 결합한다. 변경된 미리보기로 적용하면 거부한다.
- 기존 ‘최신 버전 불러오기’ API는 호환성을 유지한다. 새 화면은 명시적 버전과 검토 토큰으로 적용한다. 저장되었다는 이유로 내보내기 제한을 완화하지 않는다.

### 고온저장 보관함

- 영구 삭제는 제공하지 않는다. `archivedAt`과 이동/복원 이력을 추가하는 비파괴 DB 마이그레이션을 사용한다.
- 보관함은 화면 정리/알림 중지 기능이며 실제 실험 종료를 뜻하지 않는다. 진행 중인 기록의 경과시간은 계속 계산된다.
- 보관 시 기존 `notify_enabled`도 꺼 두어 보관함 열을 모르는 구버전 실행기의 새 알림을 막는다. 원래 설정은 별도 보존하고 복원 시 되살린다.
- 복원해도 원래 확인·전송·다시 알림 상태를 지우지 않는다. 진행 중이고 알림이 켜져 있으면 기한이 지난 미확인 알림이 발송될 수 있음을 적용 전에 설명한다.
- 새 실행기는 알림을 claim한 뒤 전송 직전에 상태를 다시 확인한다. 이미 OS에 전송 중인 알림까지 취소할 수 있다고 보장하지 않는다.
- 기존 API의 기본 목록은 보관함을 제외한다. 새 화면은 보관함 포함 조회를 사용해 검색·복원과 브라우저 기록 중복 검사를 처리한다.
- API와 실행기가 동시에 시작해도 스키마 확인·열 추가를 한 트랜잭션으로 직렬화한다. WAL 전환의 즉시 잠금 오류는 최대 10초 범위에서만 재시도하며, 이력 조회에는 시료 ID 인덱스를 사용한다.
